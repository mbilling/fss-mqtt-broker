## What is new

- **JWT verification is stricter** (jsonwebtoken 12). A token is refused when its header
  lists a critical extension the broker does not implement (RFC 7515 §4.1.11), or when
  its `iss`, `aud` or `sub` claim has the wrong type. This holds for static-key
  (`MQTTD_JWT_*`) and OIDC verification alike.

## Upgrading from 1.3.0

- **An empty HS256 secret stops the broker from starting.** This is a security fix.
  - **Before:** an `hs256_secret_file` (`MQTTD_JWT_HS256_SECRET_FILE`) that was empty or
    held only whitespace gave a verifier that accepted tokens signed with an empty key,
    which anyone can mint.
  - **Now:** the broker refuses to start and names the file. `--check-config --preflight`
    fails the same way, and a reload keeps the running verifier.
  - **Before you upgrade:** put the real secret in the file, and run
    `mqttd --check-config --preflight` on the host to confirm.
