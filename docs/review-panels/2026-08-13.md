## The false finding

Reviewers 2, 3 and 5 — three of five, independently — reported *"the release
claim does not verify: the only tag is `v0.9.0-rc`"*, and reviewer 2 built
verdict language on it. The cause was environmental: the review container's
clone fetched branch heads only, so `git tag` showed just the RC. The release is
real — `v0.9.0`, published 2026-08-07T23:44Z with 15 signed assets, tag present
in any normal clone. Costs: three reviewers spent credibility-weighted words on
a non-defect, and the synthesis had to refute its own panel.

Method fixes adopted from it (#259): fetch tags (or provide the release list) at
setup; release claims verify against the GitHub release list, never local
`git tag`; and generally, a finding resting on repository *metadata* is a claim
about the sandbox until the session running the panel re-verifies it against the
hosting platform. It is also a calibration note on the panel's own priority
signal: independent agreement measures shared **environment** as well as shared
truth — three reviewers agreeing through the same broken window still describe
the window.
