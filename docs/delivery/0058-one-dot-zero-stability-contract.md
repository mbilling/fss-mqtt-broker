  - id: 0058-T4
    title: "Config forward-compatibility decision: reconcile deny_unknown_fields with rollback within a major"
    status: done
    date: 2026-08-13
    evidence: "Decision recorded as ADR 0058 §Decisions E (issue #230). The seventeen per-table deny_unknown_fields attributes are replaced by ONE tolerant serde_ignored pass that collects the path of every unknown key, with the policy applied to the complete list: refuse (default — the typo net, error now NAMES all unknown keys and the escape hatch, instead of stopping at the first) or warn (runtime.config_unknown_keys / MQTTD_CONFIG_UNKNOWN_KEYS, env beating file for this knob since the file may be the very thing an older binary cannot read strictly). Under warn the broker boots a NEWER config with each ignored key carried on Config::ignored_keys and warn-logged at boot and on every ADR 0033 hot reload; type mismatches and malformed TOML always fail regardless. Trade recorded: warn ignores typos too, so it is not the default, the chart's --check-config gate stays strict, and the guidance is skew-window-only. Rejected alternatives recorded (blanket-lenient = permanent typo hole; blanket-strict = the rollback crash-loop). New dep serde_ignored (dtolnay, no transitive deps) through the cargo-deny gate. Tests: refusal lists all keys + names the hatch; warn boots a knob_from_the_future config and reports the path, via the file knob and the env layer; a type mismatch is never ignorable; a bad env value errors loudly. Residual for the 0039-T3 skew smoke at 1.0: a rolled-back binary reading the next minor's rendered config under warn."

SURFACE AUDIT findings, all fixed: (1) the bridge spool (spool*.redb) was the one on-disk store OUTSIDE the schema-gate contract — it now opens through gate_or_migrate with SPOOL_SCHEMA_VERSION 1, an empty registry, a pinned floor, and three tests (coverage, foreign-version-fails-closed, and unstamped-pre-gate-file-adopted-with-its-messages, since gate_or_migrate stamps a fresh/pre-gate store as current); (2) the ADR 0038 frame inventory recorded 18 frames while the enum holds 26 — rewritten as the 1.0-frozen surface, all 26 rows with posture/since (frames 18-21 proto 3, 22-23 proto 5, 24-25 proto 7 per-link), noting PROTO_MIN=6 retires protos 1-5 as pre-release history; (3) the backup older-format refusal said 'no migration path exists pre-1.0', ambiguous once 1.0 exists — reworded everywhere (code, its test, OPERATIONS, TROUBLESHOOTING, ADR 0062) to 'no migration path exists from pre-1.0 formats'. LANGUAGE: README Stability bullet + Upgrades preamble, OPERATIONS skew paragraph, CHANGELOG Versioning, RELEASING, peer.rs PROTO_MIN doc, and the operator CRD's 'may break until 1.0' clause (now the Kubernetes alpha-API convention, promotion versioned independently) all state the contract in force. GUARD: check-readme-facts.py refuses the pre-1.0 escape-clause phrases ('reshapes are permitted', 'formats may change freely', 'applies from 1.0.0', ...) in README/OPERATIONS/CHANGELOG/RELEASING whenever the workspace version is >= 1.0.0 — the flip cannot silently regress. The maintainer's v1.0.0 tag on this commit activates the contract (0051-T11)."
